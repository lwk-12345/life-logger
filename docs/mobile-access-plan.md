# Life Logger 移动端访问方案（Phase 3.3）

> 状态：阶段 A/B 已完成；移动端维持本地 Web/PWA 路径
> 日期：2026-09-22  
> 原则：本地优先、默认不暴露公网、不上传原始音频

## 1. 目标与非目标

**目标**
- 在手机上完成高频操作：查看当日时间轴/简报、确认审核队列、触发已有任务（如简报生成）。
- 保持与现有本地 Web 控制面（`127.0.0.1:8765`）同一后端与事件契约。

**非目标（本阶段不做）**
- 不做公网 SaaS、不做账号体系、不做云端 ASR/LLM 依赖。
- 不在手机端直接跑 FunASR / 重转写。
- 不默认把录音文件同步到云盘。

## 2. 推荐架构（分阶段）

### 阶段 A — 局域网只读/轻操作（推荐先做）

```
手机浏览器
  │  http://<电脑局域网IP>:8765  （仅绑定局域网或经受信隧道）
  ▼
本机 life-logger local-web（已有）
  │
  ▼
本机 output/ + SQLite / daily_summary（已有）
```

要点：
- UI 继续用现有本地 Web，补「移动友好布局」即可，不必先写独立 App。
- 鉴权：本机令牌（启动时生成一次性 token，扫码写入手机书签）或 HTTP Basic；**默认不开放匿名访问**。
- 绑定：默认仍 `127.0.0.1`；用户显式开启「局域网访问」后才监听 `0.0.0.0` / 指定网卡。
- 防火墙：仅放行本机用户确认的端口；文档明确「咖啡馆/公司 Wi-Fi 不要开局域网访问」。

### 阶段 B — 受信隧道（可选）

当人不在同一局域网时：
- 优先 **Tailscale / WireGuard** 等点对点私网，而不是把端口打到公网。
- 若必须用临时隧道（如 Cloudflare Tunnel / ngrok），必须：短时、可撤销、强制 token、禁止上传音频路径。

当前实现不内置第三方隧道进程，也不会自动创建公网 URL。用户可在 **设置 → 移动访问** 填写一个明确的受信私网 IPv4；仅允许 RFC1918 或 Tailscale `100.64.0.0/10`，重启后只绑定该接口地址。这样可让 Tailscale/WireGuard 访问而不必监听全部局域网接口。公网 IP 会被拒绝。

### 阶段 C — PWA 浏览器入口

- 当前 Web 保留同源 PWA manifest（`web/manifest.webmanifest`），用于浏览器“添加到主屏幕”。
- 自用范围不再维护独立原生壳构建链；token、CSRF、审核 API 继续由现有 Web 服务提供。
- 本地推送（简报到手机）继续通过已有 daily brief outbox / 可选直接 webhook；出站内容不携带原始音频。

### 手机捕获通路（P5-C）

```text
手机录音 / 本机音频文件
  → 已鉴权的 Life Logger Web
  → 现有 job create + same-origin file upload
  → 本机 output/local-web
  → 现有 ASR / 声源 / 事件处理链
```

- 捕获配置通过 `GET/POST /api/mobile-capture` 管理并持久化到 `preferences.json`。
- 默认显示捕获入口，但“选完后自动开始处理”默认关闭，避免误触后立即跑长任务。
- Web 捕获入口使用浏览器录音/文件选择能力；不创建第三方上传 URL，不把原始音频写入 daily brief outbox/webhook。
- 如果浏览器不支持 `capture=\"microphone\"`，自动退化为普通本机文件选择，仍走同一处理链。

## 3. 安全边界（硬约束）

| 边界 | 要求 |
|---|---|
| 默认暴露面 | 仅 localhost；局域网/隧道需显式开关 |
| 音频 | 手机捕获的原始音频只上传到当前已鉴权 Life Logger 服务；永不进入 daily brief outbox/webhook 或公网同步；预览片段需单独授权 |
| Agent API | `/api/daily`、`/api/daily-brief`、`/api/patterns` 等只读接口同样要令牌 |
| 写操作 | 审核确认/拒绝、触发任务需 CSRF/同源 + 令牌双重约束 |
| 日志 | 移动访问日志只记方法/路径/状态码，不记事件正文 |

## 4. 功能切片（实施时优先级）

- [x] **P0**：移动布局 + 令牌登录 + 当日时间轴/简报只读；窄屏今日简报已提供直接操作入口。
- [x] **P1**：审核队列确认/拒绝；窄屏按钮使用触控友好尺寸并显示操作结果。
- [x] **P2**：手动触发 brief / doctor；局域网开关与 token 配对。
- [x] **P3 最小落地**：受信私网（Tailscale/WireGuard）文档化 + 可选精确私网绑定。第三方隧道本身仍由用户独立启停，不由 Life Logger 托管。
- [x] **P4 / 阶段 C 收敛**：保留 PWA manifest；独立原生壳构建链已退出自用范围。
- [x] **P5 / 手机捕获占位**：移动端录音/文件选择入口 + `/api/mobile-capture` 配置；复用现有 job upload，自动开始默认关。

## 5. 风险与回退

- 风险：用户误开局域网访问 → 同网段可扫到服务。  
  回退：开关默认关；启动 banner 明确显示绑定地址；关闭访问开关并重启即可恢复 localhost-only。
- 风险：隧道长期挂着。  
  回退：隧道配置与 life-logger 解耦，文档强调「用完即关」。

## 6. 验收标准（实施阶段再用）

- 默认安装下，外网端口扫描不到服务。  
- 无令牌访问 `/api/*` 返回 401。  
- 手机可完成「看今日简报 + 确认一条审核」闭环，且不上传任何音频文件。
- 手机窄屏可直接从今日简报进入待复核，并可手动触发已配置的 brief outbox/webhook。
- 配置受信私网绑定后，重启只监听指定 RFC1918/Tailscale IPv4；公网 IPv4 配置被拒绝。
- Daily brief 出站与移动访问解耦：手机访问不要求把原始音频写入 outbox/webhook。
- 手机首页可直接触发 doctor；失败时跳转到系统自检详情。
- 手机捕获一份音频后，文件只出现在现有 Life Logger job/input/output 路径；daily brief outbox/webhook 中不得出现原始音频。

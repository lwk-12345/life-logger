# 声纹模板标定经验（务必先读这个再建模板）

2026-10-01/02 实测总结。**建模板这件事有一个反复踩到的坑，先看结论。**

## 结论：模板必须「同声道」，而且必须「用已确认本人的片段」来建

CAM++ 的余弦相似度对**录音声道**极度敏感。同一个人，换个麦克风，
相似度会从 0.7+ 掉到 0.3 左右，而 `self` 门槛是 0.45–0.50。
一旦掉下去，所有片段都落进 `unknown`，`should_extract_life_events` 拒绝生成事件，
**整条流水线白跑，但不报任何错。**

## 实测数据（同一个人，四种模板）

用 Apple Watch 录音里已被管线判为 `self` 的片段做测试集：

| 模板来源 | 相似度 | ≥0.45 命中 |
|---|---|---|
| H8 录音笔（原始配置） | 0.31 | 0/34 |
| AirPassport（同人同麦） | 0.42–0.52 | 部分，贴门槛 |
| 手表录音**自动挑语音段** | **0.05–0.16** | **0/8** ❌ |
| 手表录音里**已确认 self 的片段** | **0.66–0.84** | **8/8** ✅ |

跨会话验证（用会话 A 建的模板，测会话 B）：**6/6 命中，0.66–0.79**。

## 两个反直觉的点

### 1. 自动挑「有语音的片段」会建出坏模板

`scripts/build_speaker_template.py` 按能量门限挑语音段，对 AirPassport
（按键触发的单人语音）有效，**对手表录音无效**：手表录的是整个房间，
挑出来的可能是别人说话、视频外放、打字声。

**手表录音建模板必须走「先用现有管线跑一遍，再拿判为 self 的片段重建」这条路。**

### 2. 模板不是「越干净越好」，是「越同源越好」

手表原始录音是 16 kHz AAC，必须先转 WAV：

```bash
afconvert -f WAVE -d LEI16@16000 -c 1 input.m4a output.wav
```

## 建模板的正确流程

1. 用**当前**模板（哪怕很差）把一个会话跑完，拿到 `source-attribution.json`
2. 从里面筛 `source_label == "self"` 且时长 ≥ 2 秒的片段
3. 取最长的若干条，拼到约 30 秒，归一化，写成 16 kHz 单声道 WAV
4. 改 `local-config.json` 的 `template` 指向它
5. **跨会话验证**：用另一个会话的 self 片段测，相似度应 ≥ 0.6。
   只有同会话验证是不够的（自证）
6. 确认无误后重跑受影响的会话

参考实现：`scripts/build_speaker_template.py`（自动挑段版，适合单人按键链路）
本文件记录的「按 self 片段建」目前是手工脚本，见下方命令片段。

## 一条链路的模板只对它自己有效

| 链路 | 声道 | 该用哪个模板 |
|---|---|---|
| Apple Watch | 手表麦克风，连续录制 | `template-from-watch-self.wav` |
| AirPassport | MacBook 麦克风，按键触发 | `template-from-airpassport.wav` |
| H8 录音笔 | 录音笔（已停用） | 无需再管 |

`local-config.json` 只有一个 `template` 字段，**意味着只能服务当前主链路**。
2026-10-02 起主链路是 Apple Watch，所以指向 `template-from-watch-self.wav`。

如果哪天要同时支持多条链路，需要把 `template` 改成按 `capture_source` 分派，
而不是全局单值。
